# Review t8: energy session prep

Brief: briefs/t8.md      Reviewed commit: d2dc3bec37636b316f974a2e53e385de53c1a981

## Design

**Hold the live session.** Three parts of the approach hold in isolation. The shell script can round-trip the exact
settings data or key absence, the preview host makes the card's buttons dismiss it without changing habitat, and
both flags are inert when unset or set to a value other than `1`. The launch and cleanup paths still let the session
change owner state outside its settings backup.

The preview skips both Sharks hand-over calls and uses a process-local shown marker. Both modes skip the saved
arrival decision and disable the welcome from Help. The documented energy command also sets
`ASCII_ANIMALS_NO_HANDOVER=1`, which disables the hand-over and its watcher. The quiet flag alone leaves them enabled.
An energy-only Meadow selection sets `meadowTried` in the app's decoded settings in memory. The shell edit leaves any
saved value of that field alone, and loading `SettingsStore` does not by itself save the decoded settings.

## What is missing?

The session needs an exclusive settings transaction through verified cleanup, launch modes that prevent writes
outside that transaction, and a recovery procedure that identifies the test bundle and restores the owner's
original running app. The existing offscreen probe covers the card and its marker. It exits before the app delegate
launches, so it gives no evidence about the updater, wallpaper, hand-over, or quit behavior.

Independent checks on the reviewed commit:

- `swift build` and `swift build -c release --product ASCIIAnimals` completed with Swift 6.4. The linker warned about
  missing Command Line Tools search paths. `swift run -c release OceanChecks` reported **262 passed, 0 failed**.
  `bash -n Tools/energy.sh` and `git diff --check origin/meadow-t9...origin/meadow-t8` passed.
- The bare app ran only with `ASCII_ANIMALS_NO_HANDOVER=1` and `--snapshot-whatsnew-probe`. Both invocations, with
  the preview flag set and with both new flags unset, reported **22 probes, 0 failed**.
- On throwaway domains with `ENERGY_DRY=1`, normal exit (0), an invalid sleep after the write (1), and a process-group
  SIGINT (130) each restored the exact original data or key absence, verified the restore, and removed the backup.
  Plist exports before and after matched, including `arrival.v1`, `whatsNew.meadow.v1`, `whatsNew.web.v1`, and
  `onboarded.v1`. While modified, the fixture's `meadowTried`, custom count, line-up, and unknown field were intact.
  A wrong-typed input and an existing backup were rejected without modifying either. Alias, overlap, cleanup failure,
  and dry baseline cases are below.
- The live path, shell recovery against real settings, and original-app relaunch were reviewed from source. The
  owner domain, installed apps, and ASCII Sharks were left alone.
