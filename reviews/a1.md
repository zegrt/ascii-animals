# Review a1 | macOS root causes

Brief `briefs/a1.md` at `df4c13a`. Reviewed `origin/meadow-t11` at `5e3dea9`. File and line references below refer to that revision. Status is **done with concerns**.

## Design

Desktop windows are deliberately mouse-transparent. Each display draws through its own display link, while the app routes pointer events separately into Ocean, Web and Meadow. Keeping input and drawing independent is appropriate for a wallpaper. The boundary that fails is deciding whether a real mouse event belongs to exposed desktop. Several other paths make a similar substitution: a notification for current system state, an ordered window for an attended presentation, a frame submission for a presented frame, or a display ID for a recoverable system-wallpaper change.

## What is missing?

- The popup's owner, type, app activation state and whether the test clicks were on the popup, elsewhere on that display or on another display. These distinguish the two confirmed code paths in finding 1. The incident does establish that animation continued.
- Integration evidence for AppKit delivery, WindowServer window lists and Spaces, display wake and drawable recovery, permissions, and system wallpaper restoration. The live checks below are for an isolated test account or Mac in a separately authorized session. The update, hand-over and uninstall checks can use test doubles and throwaway bundles.
- `swift build` succeeded and `swift run -c release OceanChecks` ended with **275 passed, 0 failed**. The build warned about missing Command Line Tools search paths and a temporary weakly held host in the card's drawn probe (finding 5). These checks exercised offscreen rendering and pure routing, power, scene and presenter logic. No app launch, on-screen test, installed-copy inspection or defaults access was performed for this audit. The t11 fix round in the board corrections is outside the pinned revision.

## Findings

### 1. Pointer routing equates AppKit delivery and window rectangles with desktop input · high · medium

**The popup incident.** At `Sources/ASCIIAnimals/PointerMonitor.swift:23–41` there is exactly one desktop mouse source, an AppKit global monitor for moved, left-dragged and left-down. Apple says this observer receives copies of events dispatched to **other applications**. When macOS sends the event to an ASCII Animals alert or window, the callback never runs for that event. This is a per-event destination rule. Making ASCII Animals active does not by itself stop delivery of later events dispatched elsewhere, including any that go to Finder. The desktop window cannot supply the missing input through normal hit testing because it sets `ignoresMouseEvents` (`Sources/ASCIIAnimals/DesktopWindows.swift:53–57)). Apple's local observer would cover ordinary own-app dispatch, but Apple explicitly excludes events consumed by nested tracking loops such as menus, controls and window dragging. [Apple Event Handling Guide](https://developer.apple.com/library/archive/documentation/Cocoa/Conceptual/EventOverview/MonitoringEvents/MonitoringEvents.html), [Apple local monitor reference](https://developer.apple.com/documentation/appkit/nsevent/addlocalmonitorforevents%28matching%3Ahandler%3A%29).

**A foreign popup can cause the same visible result by a different path.** If the callback runs, the app rejects both movement and down when **any** returned foreign window rectangle contains the sampled point. The scan includes every on-screen non-desktop-element window of layer zero or higher with reported global alpha at least 0.01, and ignores its own PID wholesale (`PointerMonitor.swift:35–61`). The router does no z-order, shape, or hit-target test (`Sources/OceanKit/Domain/PointerRouter.swift:16–23`). A click over an actual popup is correctly excluded. An accepted rectangle for a transparent backing surface, a region around a rounded window, or a display-sized overlay would also exclude geometrically exposed desktop. This path can account for a whole dead region only if the accepted rectangles cover that region. In the other direction an Animals window that appears above the wallpaper is absent from the blocking list, so a foreign-dispatched event at that point can affect the habitat behind it. The code uses bounds, PID, layer and alpha, without title, sharing state or pixels. Apple's window metadata documentation gives no basis to require Screen Recording for this path. Which surfaces the real prompt exposes in this API needs live evidence. [Apple window list](https://developer.apple.com/documentation/coregraphics/cgwindowlistcopywindowinfo%28_%3A_%3A%29), [Apple window bounds](https://developer.apple.com/documentation/coregraphics/kcgwindowbounds), [Apple WWDC on window metadata and privacy](https://developer.apple.com/videos/play/wwdc2019/701/?time=1995).

**Why the animals kept moving.** A routed miss calls `pointerLeft` on every scene and never calls `pointerDown`. A delivery miss leaves the last pointer state latched. Neither changes the run mode, the simulation clock or the display links (`Sources/ASCIIAnimals/OceanDirector.swift:55–85,95–134,274–294`, `DesktopWindows.swift:82–88`, `Sources/OceanKit/Domain/HabitatScene.swift:56–61`). Ocean therefore keeps swimming and can retain the old avoidance point, Web keeps stepping with its old pointer state and Meadow can treat the last valid point as a held pointer even while the person is using a popup (`Sources/OceanKit/Domain/OceanSim.swift:27–30`, `Sources/OceanKit/Web/WebWorld.swift:283–296`, `Sources/OceanKit/Meadow/MeadowWorld.swift:796–837,875–914`). Continued desktop animation also argues against a global power pause or complete main-thread blockage during the observed interval. The link runs in common modes, which include AppKit's modal and event-tracking modes by default. App-owned alerts during live operation include updates and errors (`UpdateService.swift:114–122,180–187,224–229`), the login-item error (`StatusMenu.swift:429–433`), uninstall confirmation (`Uninstaller.swift:7–16`), and a running Sharks instance that refuses to quit (`SharksHandover.swift:55–73,94–102`, all under `Sources/ASCIIAnimals/`). Startup hand-over dialogs run before the local director starts (`main.swift:39–43,49–75`, `SharksHandover.swift:107–140)). Notification authorization is asynchronous and the system owns the prompt experience (`UpdateService.swift:200–206`). The prompt's event destination and window metadata are unknown, so the report cannot attribute the friend's incident to an Animals modal or to a system window in particular. [Apple modal alerts](https://developer.apple.com/documentation/appkit/nsalert/runmodal%28%29), [Apple run-loop modes](https://developer.apple.com/library/archive/documentation/Cocoa/Conceptual/Multithreading/RunLoopManagement/RunLoopManagement.html), [Apple notification authorization](https://developer.apple.com/documentation/usernotifications/unusernotificationcenter/requestauthorization%28options%3Acompletionhandler%3A%29).

**Other failures at the same boundary.** The event's type is paired with the cursor's position at callback time (`PointerMonitor.swift:35–41`), which can move since mouse-down and turn a genuine click into a miss or place it in the wrong habitat. No movement means no re-evaluation when a popup opens, closes, or moves, the desktop changes Spaces, or an own-app event takes over. The 50 ms geometry cache survives starts and stops, and a failed window lookup becomes an empty blocker list (`PointerMonitor.swift:23–32,45–55`). A missed monitor registration is silent. Left drags can enter bare desktop from a gesture captured by another window. Actual click policy should account for that ownership where it is observable.

**Fix and proof.** Give desktop input one explicit contract covering source, position at event time, gesture ownership, desktop eligibility and pointer invalidation. Combine global and passive local delivery where supported, and handle nested-loop or unavailable-source behavior explicitly. A common-mode, bounded mouse-position sample can clear and reconcile hover on geometry or delivery gaps, with no synthesized clicks. Evaluate fresh click eligibility with current display/window identity and ordering, and distinguish owned wallpaper from owned UI. Treat bounds as a conservative approximation where public APIs lack hit-test information. Preserve clicks for the receiving app, avoid depending on keyboard or screen-capture permission, and measure the cost of window-list sampling. Unit-test delayed/moving clicks, stale hover, missing metadata, a popup on one display and an exposed target on another. In a supervised trace try an Animals alert, another app's small modal, a system authorization prompt, notification banner, hidden Dock/menu bar, and own and foreign menus. Record callback type/source, event point, run-loop mode, blocker PID/layer/rect, route decision and presented-frame counter. A missing callback and a callback rejected by a specific rectangle are separately observable.

### 2. System wallpaper changes have a narrower recovery address than their side effects · high impact · large

`Sources/OceanKit/Domain/WallpaperMemory.swift:33–43,70–94` keeps one original per display and permits replacement by original **URL** equality or ownership by directory. The app separately snapshots the display's current desktop image at enqueue and when a still is ready (`Sources/ASCIIAnimals/SystemWallpaper.swift:44–92`). Different Spaces can have the same image with different options, and a person can change options while keeping the image. Both pass the URL guard and later get the first options back. An in-flight render can run across a Space switch and the second check can still match. Changes to wallpaper settings, theme or layout only cancel delayed work. Already queued renders share a generation until `restoreAll` increments it, and the commit uses an old screen object and look even after a newer request is known (`SystemWallpaper.swift:18–21,44–80`, `main.swift:62–73,160–185`). Failed setting also reaches pruning. Pruning protects the newly generated URL and the most recent filenames, with no view of which stills other Spaces use.

Restoration sees only the current desktop images of enumerated screens, forgets the per-display original after the first successful restore and has no active-Space reconciliation. A still in another Space or on a detached display can outlive Quit or turning matching off. Menu Restore calls twice when it changes the setting, and quit retries only if matching is enabled (`SystemWallpaper.swift:95–147`, `StatusMenu.swift:413–417`, `main.swift:166–168,190–195`). Uninstall proceeds to delete the stills and restore memory even when restoring was skipped or failed, then the GUI exits successfully. The CLI additionally requires Metal just to restore and continues after its bounded wait for another copy (`Uninstaller.swift:21–43`, `main.swift:153–158,235–256`). Given default-on matching (`Sources/OceanKit/Domain/Settings.swift:27`), the ordinary path writes this external state. Apple documents screen-scoped desktop APIs, their main-thread requirement and notifications of Space transitions. Those APIs do not provide this implementation with a stable address for every Space's original. How URLs, individual options and native dynamic wallpapers round-trip on supported macOS versions needs a live check. [Apple desktop image setter](https://developer.apple.com/documentation/appkit/nsworkspace/setdesktopimageurl%28_%3Afor%3Aoptions%3A%29), [Apple Space change notification](https://developer.apple.com/documentation/appkit/nsworkspace/activespacedidchangenotification).

**Fix and proof.** Make changing and restoring external state one recoverable transaction. Require fresh settings, layout and expected original at commit. Journal the original and its options against the exact installed still and keep that image and journal until restoration succeeds. Reconcile on relevant wake, display and Space transitions. If public APIs cannot give the restoration guarantee for a configuration, limit which surfaces are changed and make that limit explicit. Restore without a render device and preserve recovery material on failure, including uninstall. Inject failures for read, write, restore and removal. On an isolated account try two Spaces with identical image URLs and different options, a switch mid-render, display detach, matching off, quit, restart after interruption, and uninstall with one failed restore.

### 3. Sleep, lock, visibility and held frames are collapsed into one mode with no recovery owner · high · medium

- `Sources/ASCIIAnimals/SystemSignals.swift:15–49,71–89` snapshots battery, Low Power, accessibility and thermal at launch, but display sleep is a sticky notification bit. Wake and periodic reconciliation read lock, console and two screensaver bundle IDs only. A missed wake can leave the desktop paused indefinitely and can keep the Meadow card waiting even if its direct `CGDisplayIsAsleep` check would pass (`WhatsNewCard.swift:94–101`). A launch with a sleeping screen has the opposite initial assumption. An unavailable session dictionary means unlocked and on-console, while a running screensaver process is treated as proof the saver is showing. A delivered screen-saver-stop edge blindly clears that one bit. Launch or wake with delayed, reordered or missing notifications and a saver process that stays running are live questions. Apple's distributed notifications may be dropped. Core Graphics gives a per-display sleeping state. [Apple distributed notifications](https://developer.apple.com/documentation/foundation/distributednotificationcenter), [Apple Quartz Display Services](https://developer.apple.com/documentation/coregraphics/quartz-display-services).
- The t11 energy timer fix is in `main.swift:99–123`. The same default-mode dependency remains in the 30 s fallback poll and IOKit AC/battery source (`SystemSignals.swift:37–55`), the two greetings' typing/blink timers (`OnboardingController.swift:437–471`, `WhatsNewCard.swift:666–677`), the card presenter looker (`WhatsNewCard.swift:51–63`) and the hourly updater (`UpdateService.swift:48–58`). Tracking the app's own menus can delay their work while display links and the Settings status timer in common modes continue. Presentation and updates may legitimately defer while a menu is tracking. Power reconciliation needs an explicit latency contract. Changing timer modes does not make a genuinely blocked main thread responsive. [Apple run-loop modes](https://developer.apple.com/library/archive/documentation/Cocoa/Conceptual/Multithreading/RunLoopManagement/RunLoopManagement.html).
- `Sources/OceanKit/Domain/PowerPolicy.swift:51–68` merges environmental stop and user pause into `.paused`. `Sources/OceanKit/Domain/Dissolve.swift:29–39,71–90` later uses `userPaused` as permission to draw even if locked or asleep. `Sources/ASCIIAnimals/OceanDirector.swift:55–91,105–134,181–191,238–261` re-arms a `.still` frame on any policy application, tries to draw owed user-pause changes when the environment also says stop, and retires a held-frame attempt after a missing drawable or command buffer with no bounded retry. For example in Low Power a failed first still can remain blank until a later mode or visibility change. The initial `visible || !presented` exception can also keep an unpresentable screen eligible for expensive live retries, and a covered desktop can resume with an old user-held image depending on whether the failed attempt was ever re-armed. Screen visibility is folded from AppKit window flags (`DesktopWindows.swift:37–41,107–130`). Apple allows `.visible` even for transparent or nonrectangular windows whose bounds intersect visible regions. What this reports across Mission Control, full-screen Spaces, Stage Manager and partial display sleep requires live verification. [Apple occlusion state](https://developer.apple.com/documentation/appkit/nswindow/occlusionstate-swift.struct/visible).
- The desktop, card and other previews have different policy owners. The card throws away the live cap and explicitly clears Reduce Motion before deriving preview mode (`Sources/OceanKit/Domain/WhatsNew.swift:211–233`), then uses `LiveOceanView`'s 30–60 Hz request. That view starts when attached to a window, even if a caller just stopped it for Low Power before attachment. About and the welcome also use this view, with no equivalent power/visibility lifecycle (`Sources/ASCIIAnimals/LiveOceanView.swift:131–158`, `AboutWindow.swift:79–111`, `OnboardingController.swift:332,368–379,412–443,645–655`, `WhatsNewCard.swift:597–625,637–640,694–714`). The card's held image can also be cached across changes of appearance or line-up. Opening these surfaces can increase work when the desktop says it is resting. Respecting Reduce Motion in title animations alone leaves the live habitat moving. The attach/stop order and wake/resume behavior need live confirmation.

**Fix and proof.** Maintain current session and per-display eligibility separately from user intent and from whether a newer picture is owed. Observe system edges, reconcile current values at startup, wake, unlock and display changes, and represent unknown readings explicitly. Let an eligible surface retry a pending frame with bounded backoff and acknowledge it on actual success. Use an explicit policy for each preview surface's visibility, requested cap and reduced motion. Test combined user pause and lock, a missing wake edge, one sleeping display, failed first drawable and eventual success without another OS event, redundant updates in still mode, attachment during a stopped policy and appearance changes while holding a still. Verify on the supported macOS range with menu tracking, clamshell reconnect, fast user switching and sleep/wake.

### 4. The update path treats active-app state, feed results and installation as one-step decisions · high impact · large

- `Sources/ASCIIAnimals/UpdateService.swift:48–68,86–138` checks only `NSApp.isActive` for being busy. A visible Settings window that lost focus, an inactive nonactivating card, open menu tracking, or a user editing after the download starts are distinct from that bit. A cached release can immediately take the automatic path at startup, ahead of onboarding (`main.swift:79–93`). Once started, the worker replaces the bundle without revalidating the automatic-update preference or UI activity (`UpdateService.swift:143–164`, `SelfUpdater.swift:38–70,101–113`). The UI specifically promises to wait while Settings is open (`SettingsView.swift:701–704`). Apple exposes frontmost application and window lifecycle separately. Track the actual surfaces and operations that cannot be interrupted. Stage opportunistically, then recheck immediately before committing an automatic replacement. Test Settings visible but inactive, a notification-driven/manual update, disabling auto while downloading, and reopening Settings between staging and install. [Apple application activation](https://developer.apple.com/documentation/appkit/nsrunningapplication/isactive).
- `UpdateService.swift:86–124,168–221` persists every check, including a transient network failure, as a last check and maps an unparseable HTTP 200 feed to “You're up to date.” It can also leave an old ETag beside a newly cached response missing ETag. The next automatic attempt is gated by the 20 h normal interval (`Sources/OceanKit/Domain/Updates.swift:47–75,109–129`). Notification authorization is requested by a background outcome, and `notified` is saved when authorization succeeds even if adding the request fails. The update-success marker is removed before checking authorization or successful submission. In a hidden-icon configuration those paths can leave no visible notice. Track a valid release cache plus its validator as one record, use bounded retry for failures, ask for permissions in context, and separate authorization, submission and actual presentation. Test offline-to-online, malformed 200, 304 after a 200 with no ETag, denied/changed settings, scheduling error and a stale notification after a newer tag is available. [Apple authorization and settings](https://developer.apple.com/documentation/usernotifications/asking-permission-to-use-notifications), [Apple notification scheduling API](https://developer.apple.com/documentation/usernotifications/unusernotificationcenter/add%28_%3Awithcompletionhandler%3A%29).
- `SelfUpdater.swift:73–133` verifies a checksum from the same feed, candidate version and bundle identifier, then signature integrity with no supplied publisher requirement. The check's signed identifier is a label, and the release build uses ad hoc signing (`Tools/build.sh:61–65`). The result relies on the release channel for provenance. If updater policy promises independent publisher authentication, deploy a release signing authority or a separately pinned signed manifest before accepting unattended replacements. Keep the current download integrity and version checks. `SelfUpdater.swift:135–147` terminates even if the relaunch process could not start, and the helper does not report a failed re-open. Also `AppDelegate.applicationDidFinishLaunching` counts any sibling with the same bundle ID and calls normal termination on refusal, which can clear the crash marker of the accepted process (`main.swift:30–35,190–195`, `Log.swift:51–68)). Use single-instance ownership covering crash metadata and a replacement/relaunch handoff with failure reporting and recovery. Test on throwaway bundles with app identity mismatch, a different signing authority, failure to schedule relaunch and simultaneous launch. [Apple code signing and code requirements](https://developer.apple.com/library/archive/technotes/tn2206/_index.html).

### 5. Presentation and acknowledgement have different lifetimes · medium · medium

The already routed card click, notch and target-display changes address three triggers on the Meadow card. The first-run tour and Sharks Web welcome still have their own presentation lifecycle. `Sources/ASCIIAnimals/OnboardingController.swift:16–60` makes a once-only launch decision then uses a fixed delay. It checks renderer and screen availability, but does not check lock, screensaver or sleep. It activates and makes an above-apps, all-Spaces overlay key (`OnboardingController.swift:349–394,412–439`), then marks multiple welcomes seen after three seconds of being key on the check, or on a generic `finish`. Display changes, losing activation and another titled window becoming key call that same default-seen finish before the three-second check (`OnboardingController.swift:423–439,611–642`). A startup interrupted before the first beat can therefore record all three introductions as seen. The full-screen overlay remains interactive during its exit fade, although the model already considers it finishing. Actual sequencing during an overlapping startup alert, login, display change or Space switch is a live check. [Apple window ordering](https://developer.apple.com/documentation/appkit/nswindow/orderfrontregardless%28%29), [Apple window occlusion](https://developer.apple.com/documentation/appkit/nswindow/occlusionstate-swift.struct/visible).

The Meadow card has a better machine-state gate, but at this revision its panel starts at alpha zero, `orderFront` verifies only order state and a screen, and the presenter commits once `open` returns. Later, screen reconfiguration closes the card, and lock or sleep only affects its preview. Treating opening as a durable acknowledgement leaves a separate race even without outside-click dismissal. The card's non-key Esc monitor also depends on events going to ASCII Animals through ordinary AppKit dispatch. Fix round 1's close button and explicit dismissal contract should preserve the other app's keyboard and define when Esc can be honored (`Sources/ASCIIAnimals/WhatsNewCard.swift:94–130,180–183,609–664,680–684`, `Sources/OceanKit/Domain/WhatsNew.swift:59–129`). The drawn probe checks alpha from a single-window capture or view bitmap after ordering. Its offscreen coordinates are a convention and it still orders a real panel. It establishes that the tested content drew, with no evidence of what covered it or whether it was seen. The fallback uses a legacy capture symbol dynamically, and the drawn probe's temporary `ProbeHost` is released immediately because the wrapper holds it weakly. The normal preview wraps the retained app delegate (`WhatsNewCard.swift:84–92,135–160,417–453,470–488,760–802`). [Apple `isVisible` semantics](https://developer.apple.com/documentation/appkit/nswindow/occlusionstate-swift.property), [Apple local event monitoring](https://developer.apple.com/documentation/appkit/nsevent/addlocalmonitorforevents%28matching%3Ahandler%3A%29).

**Fix and proof.** Use one presentation lifecycle that distinguishes waiting, eligible, opened, and acknowledged. Interruptions should preserve eligibility unless the user reached the content or explicitly dismissed it according to that greeting's policy. On a display move or Space switch, withdraw or revalidate placement and eligibility before consuming a showing. For the approved Meadow timer, derive elapsed duration from an injectable monotonic clock and accumulate only eligible, awake and unlocked intervals, including hover rules and process/restart transitions. The pinned code uses wall time for its close diagnostic (`WhatsNewCard.swift:635–640,731–738`), which can go backward or include unavailable time. A system-uptime reading by itself also includes periods with an awake but locked screen. Test interruptions before content, explicit dismissal, launch locked, changing Spaces or closing the lid as a card appears, working in another app and time changes during hover and retry. Keep capture evidence distinct from whether a human could see a window. [Apple system uptime](https://developer.apple.com/documentation/foundation/processinfo/systemuptime).

### 6. Display relayout assumes an enduring index and publishes state before successful setup · medium · large

- `Sources/ASCIIAnimals/OceanDirector.swift:148–191` returns on an empty AppKit screen list and leaves the previous windows, scenes, mode and pointer targets intact. The drawing filter can also produce an empty set after the main-screen guard, without explicitly recalculating aggregate visibility from that set. It builds replacement scenes before screen fits finish and keeps rendering on an existing screen if fit throws. `Sources/ASCIIAnimals/DesktopWindows.swift:91–100` mutates the scene, rect, window, backing scale and drawable size before viewport resize. `Sources/OceanKit/Render/OceanRenderer.swift:130–165` publishes geometry before potentially failing allocations for textures and atlas, and can leave a mixed generation of state. An allocation failure can leave a blank or mismatched display, and the director's error is sticky even after successful reconfiguration (`OceanDirector.swift:201–204`, `OceanStatus.swift:28–30,69–75`, `StatusMenu.swift:166–168`). Window-list delivery, ID/scale changes and resource failure frequency need live evidence. AppKit documents that the list can change and discourages caching it. [Apple `NSScreen.screens`](https://developer.apple.com/documentation/appkit/nsscreen/screens).
- Shared plans are normalized to the desk's minimum X/Y and store views and terrain in current enumeration order (`Sources/OceanKit/Domain/SceneLayout.swift:29–46`). `HabitatScene.arrange` reuses a scene based on a **set** of display IDs, then calls relayout on an order- or origin-only difference (`Sources/OceanKit/Domain/HabitatScene.swift:23–25,42–53,67–87`). A main-display change can reorder the same two screens. An Ocean shark's home and doorway remain indexed by the old order while their indices are in range (`Sources/OceanKit/Domain/World.swift:119–146`). Web reconstructs webs and animals even for an order/origin-only move (`Sources/OceanKit/Web/WebSim.swift:23–28`, `WebWorld.swift:103–177`). Meadow retains scene-local animal and pointer coordinates and only projects or clears them if they land outside the new terrain (`Sources/OceanKit/Meadow/MeadowWorld.swift:735–788`). A stationary cursor can therefore be active at the wrong physical point after reconfiguration. A separate Meadow sim also counts every retained sim's departing butterflies as taking up desk room, while departure depends on that screen's simulation ticking. A covered display can delay new arrivals on an uncovered one until it resumes (`Sources/OceanKit/Meadow/MeadowSim.swift:59–100`, `MeadowWorld.swift:900–914`, `Sources/ASCIIAnimals/DesktopWindows.swift:107–110`). Preserving the 12 cap is correct, but covered-scene progress needs explicit semantics.
- The primary `screens.first` used for an AppKit-to-Quartz coordinate flip is appropriate: it identifies the screen at the global origin, while `NSScreen.main` follows keyboard focus. The risk is obtaining three independent snapshots at dispatch and relayout (`PointerMonitor.swift:35–39`, `DesktopWindows.swift:139–149`, `OceanDirector.swift:148–155`). Focus-based placement elsewhere has the opposite need. Settings sizes itself using `NSScreen.main` before activation, then centers and restores an autosaved frame only on first creation. About also creates and centers once (`Sources/ASCIIAnimals/SettingsView.swift:739–759`, `AboutWindow.swift:79–111`). They never explicitly constrain retained placement to a current display's usable frame on reopen. AppKit may relocate those windows itself, so probe reopening after detaching the last-used secondary, switching primary, changing scaling and entering full screen. [Apple `NSScreen`](https://developer.apple.com/documentation/appkit/nsscreen), [Apple current usable frame](https://developer.apple.com/documentation/appkit/nsscreen/visibleframe).

**Fix and proof.** Build a display snapshot keyed by ID, including transform, backing scale and eligibility. Pass it into layout and routing together. Decide which state follows a physical display and rebase it by identity, invalidate input on geometry changes and preserve unchanged scenes. Build new per-screen GPU state transactionally and publish only coherent generations. Treat zero displays explicitly and clear recoverable errors on success. Feed reordered IDs with equal geometry, changed origin, mixed Retina/1x, mirrors, a disconnected gap, one sleeping display and viewport creation/resize failures into checks. Verify wallpaper placement, click location, simulation continuity and window reopen after hot-plug and clamshell changes live.

### 7. GPU backpressure can starve UI work, and frame submission is treated as presentation · medium · large

The desktop and preview display links call `CAMetalLayer.nextDrawable` on main (`Sources/ASCIIAnimals/OceanDirector.swift:95–134`, `LiveOceanView.swift:136–158`). Apple documents that drawable acquisition can wait up to a second when its pool is exhausted with the timeout enabled. The renderer can also wait indefinitely on in-flight slots while encoding or resizing (`Sources/OceanKit/Render/OceanRenderer.swift:130–139,202–218,303–319`). The desktop, preview and still jobs share the app renderer's one queue where available (`OceanRenderer.swift:14–28`, `Sources/ASCIIAnimals/OceanPreview.swift:59–87`, `SystemWallpaper.swift:62–68`, `WhatsNewCard.swift:602–607,694–709`). The welcome and About warming path spins through steps and submits one second of warmup commands synchronously on main, and the card renders a GPU readback synchronously on transition to still (`LiveOceanView.swift:66–115`, `WhatsNewCard.swift:568–584,694–709`, `Sources/OceanKit/Render/StillRenderer.swift:13–44,110–138`). Blocking here could delay **both** input and drawing, and has a different signature from the popup where motion continued. The hand-over and reporting also have synchronous waits, detailed in findings 8 and 10. [Apple drawable acquisition](https://developer.apple.com/documentation/quartzcore/cametallayer/nextdrawable%28%29), [Apple Metal command buffer completion](https://developer.apple.com/documentation/metal/mtlcommandbuffer/waituntilcompleted%28%29).

The first desktop frame fades in after a **scheduled** handler and increments counters after **commit**, including the counters t11 calls actual frame rate. Neither proves presentation, and a scheduled callback for an obsolete display can still arrive. A held frame is also cleared at commit. Offscreen reads wait for completion and then read without checking command buffer status (`OceanDirector.swift:118–141`, `DesktopWindows.swift:113–123,132–137`, `main.swift:99–123`, `StillRenderer.swift:110–138`, `LiveOceanView.swift:198–218`). `preferredFrameRateRange` is a request that may be constrained by the system. The menu/status reports the policy target as fps (`DesktopWindows.swift:102–105`, `OceanStatus.swift:32–40`). The t8 log can support a **submission**-rate claim. A mismatch with presented fps on the measured desk remains untested. [Apple command scheduling](https://developer.apple.com/documentation/metal/mtlcommandbuffer/addscheduledhandler%28_%3A%29), [Apple drawable presentation callback](https://developer.apple.com/documentation/metal/mtldrawable/addpresentedhandler%28_%3A%29), [Apple preferred frame-rate range](https://developer.apple.com/documentation/quartzcore/cadisplaylink/preferredframeraterange).

**Fix and proof.** Keep main-thread rendering input bounded, coalesce obsolete still jobs, bound work admitted to shared GPU resources and keep still/warmup work out of the UI callback. On pressure skip live work for that surface and leave a held frame owed. Check completion status for readback, use presentation results for first-visible/held acknowledgements and frame-rate evidence when available, and ignore callbacks from retired generations. Inject delayed GPU completion, missing slots and drawable failure. In an authorized multi-display run trace callback latency, queue waits, submissions and presentations while dragging, switching habitat, and creating previews.

### 9. Render cadence, elapsed time and simulation pacing are coupled · medium · medium

`Sources/OceanKit/Domain/OceanClock.swift:13–31` ties its four-step budget to display callbacks, discards any remainder on four steps, and clips a long interval to 0.1 s. With a steady 15 Hz link and 1.5× speed, six fixed 60 Hz steps per callback are requested and only four can run. Any of battery, opted-in Low Power or serious thermal state can impose 15 Hz even if 30 or 60 fps was selected (`Sources/OceanKit/Domain/PowerPolicy.swift:45–57`). On a 15 Hz link at normal speed, a slight delay reaching four steps can discard fractional time even when no whole step needs discarding. With multiple links the scene takes the largest timestamp seen, so actual step cadence can vary between a single eligible screen and two. The simulation clock is reset on rebuild but not explicitly on first live frame after an environmental stop (`Sources/OceanKit/Domain/HabitatScene.swift:35–40,56–61`, `Sources/ASCIIAnimals/OceanDirector.swift:55–76,95–116`). Preserve fractional remainder when no complete step is dropped. Derive shared transition progress from one nondecreasing sample and keep physical pointer hold timing distinct from render throttling. Drive cadence tests with 15/30/60 and mismatched and irregular timelines, 1×/1.5×, sleep/resume, and two screens crossing the dissolve midpoint in opposite timestamp order.
