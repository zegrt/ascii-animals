# Review t9: The welcome and what's-new card for the Meadow

Brief: briefs/t9.md      Reviewed commit: 4e6e990

## Design

The small nonactivating panel fits option C. It cannot become key or main, orders itself forward without activating the app, and has no Return binding. Outside mouse events are observed without cancelling them. Try the Meadow updates the saved habitat through the same settings path as the welcome. The director runs the existing dissolve when the desktop is animating and updates the still when held. The card fades independently.

The normal launch choices hold. A new install keeps its original `Arrival.since31` and gets the tour. A returning onboarded Ocean or Web user gets the Meadow card once. A Sharks arrival still gets the existing Web card first when due, with the Meadow card deferred to a later launch. An earlier Meadow selection persists `meadowTried` via the settings store and suppresses both the card and the menu badge. Dismissing the card keeps the badge until the habitat is tried, as designed. After teardown, the preview display link is invalidated, monitors and timers are removed, the panel is closed, and the controller releases the session. The callbacks back to the session are weak. This was verified by tracing ownership, with runtime limitations below.

- `swift build` passed on Apple Swift 6.4, as did explicit debug and release builds of `ASCIIAnimals`. `swift run -c release OceanChecks` passed **253 checks, 0 failed**, including launch eligibility, Sharks hand-over, fixed Ocean rendering, Web rendering, and dissolve checks.

The fallback has no arrow, sits at the upper right, and reads “Keep the Web.” The app card takes less space than the mock-up and its preview framing differs (finding 7).
- Rendered the app's `--snapshot-onboarding` for the first beat in dark and light, the Meadow selection, the Meadow's remaining beats, Make it yours in both appearances, and the Web card. Compared with d1's `welcome-0-*`, `welcome-5-*`, and `today-web-card-dark.png`. The welcome has all three habitat chips with Ocean selected by default. ## What is missing?

- The launch checks simulate saved fields by hand. They cover the usual decision table, while the uncompleted 3.0 tour, pending presentation, overlapping welcome, and power changes while waiting or visible have no regression checks.
- The snapshots render the still and use a synthetic menu bar. Live first-click delivery, outside-click pass-through, focus with another app in use, relock timing, display changes, the live dissolve, and post-close CPU were unverified at runtime. The review ran the app only through its offscreen snapshot flags.

## Findings

| # | Finding | Where | Cause group | Fix size |
|---|---|---|---|---|
| 1 | A wake or unlock can spend the once-only flag on an invisible card. After the polling timer first sees an accessible screen, it waits another second and calls `present` without checking power or screen state again. Relock, switch users, or lose the display in that interval and the panel is still constructed and marked seen. With no screens, the fallback also indexes an empty array. At startup, an already-asleep display can be missed because `displaysAsleep` starts false and is changed by notifications. Recheck live session and display state at presentation, keep it pending while unavailable, and record the flag only after ordering onto a usable display. | `WhatsNewCard.swift:25–54, 269–276`, `SystemSignals.swift:15–33`, `PowerPolicy.swift:5–10` | Presentation eligibility | Medium |
| 2 | The Help welcome can start while the Meadow card is still on screen. `dismiss()` starts an asynchronous fade and the welcome starts immediately. It also leaves both delayed presentation blocks outstanding. A short manual welcome can mark the flag and finish before a delayed callback, whose only eligibility checks are current windows and the chosen habitat. Cancel pending callbacks, recheck the persisted flag, and finish removing the panel before opening the welcome. | `OnboardingController.swift:34–56`, `WhatsNewCard.swift:25–62, 344–372` | Presentation eligibility | Medium |
| 3 | While ASCII Animals is active, the local monitor consumes every Esc before AppKit can dispatch it, including Esc aimed at Settings or a cancellable sheet. Use the active app check, close the card, and pass the event on to the window that owns it. Also make the fading panel click-through once dismissal starts so it releases that part of the underlying UI immediately. | `WhatsNewCard.swift:309–323, 344–361` | Input routing | Small |
| 4 | Low Power Mode is sampled only when the session is created. A live card keeps its display link after Low Power Mode turns on, and lock, sleep, screensaver, and session changes never reach the card. The display configuration observer only handles geometry changes. React to the existing power signals so the preview holds a still in Low Power Mode and stops rendering when the card cannot be seen. | `WhatsNewCard.swift:254–267, 324–340`, `main.swift:46`, `LiveOceanView.swift:131–157` | Preview lifetime | Medium |
| 5 | An upgrader with saved 3.0 settings whose original tour was never marked seen is classified as `before31` but gets the full-screen tour. That tour sets the Meadow flag, so this user never gets option C. The new upgrade check only exercises `onboarded: true`. Cover the saved-settings case and route upgrades to the small card while preserving the Sharks Web precedence. | `Settings.swift:212–221`, `Handover.swift:101–106`, `OnboardingController.swift:46–54`, `AppChecks.swift:229–251` | Launch decision | Small |
| 6 | When an icon frame matches no current display, the caller falls back to the primary screen but still passes the old frame. The arrow and vertical position then use the stale coordinates. AppKit also documents that `NSStatusItem.isVisible` can stay true when the application menu obscures the item. Use the top-right fallback when the status button has no usable on-screen anchor. Fit the card to the chosen visible frame, since a 400 pt visible width currently puts the hidden card's left edge 72 pt offscreen. | `WhatsNewCard.swift:71–90, 269–276`, `StatusMenu.swift:74–78` | Placement | Small |
| 7 | Both stills visibly cut butterflies at the left, right, and bottom preview edges. The flowers mostly show as fragments. The approved option C still centers a recognizable butterfly and bloom. The snapshot uses the same frame as Low Power Mode, where the view never gets a clearer moment. Frame that still with a readable butterfly and flower in both appearances. | `WhatsNewCard.swift:238–251`, `whatsnew-c-dark.png` and `whatsnew-c-light.png` on design-d1 | Preview framing | Small |
| 8 | The Keep chip holds the habitat captured at opening. If an Ocean user switches to Web by keyboard in the app while the card is up, the card still says “Keep the Ocean” and leaves them on the Web. Dismiss on an external habitat change or update the label from the current setting. | `WhatsNewCard.swift:64–67, 185–205, 254–260, 439–452` | Input routing | Small |
