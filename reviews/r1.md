# r1 right-size

Verdict: changes requested

Reviewed `971a216..5db562e` on `origin/meadow-r1b` against the Right-size brief and the director's live trace.

## Findings

1. **Should fix — a click can land under a window or on the wrong display.** `Sources/ASCIIAnimals/PointerMonitor.swift:61–78`. The window number describes the event, but the point comes from `NSEvent.mouseLocation` when AppKit delivers the callback. If a user clicks exposed desktop and moves into a window or across a display boundary before the callback runs, the earlier desktop verdict lets the later point bypass occlusion. The wallpaper can splash or bloom at the later point. On 971a216, rectangles still blocked the point if the cursor had moved over a normal foreign window. Read the point and window number from the same CG event. If a down lacks an event-time point, suppress its wallpaper action. Check a desktop click delivered after the cursor crosses a window edge or a display boundary.
2. **Should fix — a stale window verdict can keep the wallpaper blocked or let it react through a window.** `Sources/OceanKit/Domain/PointerRouter.swift:79–88`. A cache hit skips the window list indefinitely until a Space or display change, a monitor restart, or a capacity reset on another miss. The cache can therefore carry a desktop verdict into an ordinary window if a window is raised out of the desktop layer under the same ID or that ID is reused. A first lookup that misses the on-screen list also records an unknown verdict indefinitely. If that ID subsequently resolves to the desktop, a banner can block moves and clicks there again via the rectangle fallback. Expire stale classifications and retry misses at a bounded rate while events arrive, keeping list reads off the per-move path. Check a missed desktop ID that later appears, and a cached desktop ID that becomes a normal window without a Space or display change.

## Behavior and cost

- The banner fix works when the event names a listed desktop-level window. The same routing decision handles moves, drags and downs, and only a routed down triggers a splash or bloom. The earlier live trace supports that window field for the banner case. The release checks exercise the router with fake window lists.
- A resolved normal app window, Settings, About, a menu, the Dock or the menu bar at layer 0 or above blocks a delivered event and clears the habitat's pointer target. The passive monitor leaves Finder's clicks alone. Finder desktop and icon windows below layer 0 remain eligible for the wallpaper, as they were under the old rectangle filter.
- A delivered blocked or out-of-viewport event clears the stored pointer. Space and display notifications clear both caches, and the next event routes through the current viewports. The global monitor still has its existing own-app delivery limits. If a menu or a Space switch takes away the pointer without an observed event, the last target can persist until input is seen again. The right-size brief drops still-pointer sampling. I left live delivery, menu tracking and Space transitions to the director's supervised run.
- The stable desktop fixture alternates two desktop IDs with the banner up. One list read covers 3,600 moves. Resolved desktop hits skip the rectangle path entirely. The fallback still reads on the old 50 ms motion cadence and fresh on down.

### Regression

**An unrelated miss can swallow a desktop click or let the fish react through a new window.** `Sources/OceanKit/Domain/PointerRouter.swift:89–95` applies one `lastMiss` to every uncached ID. In an offscreen comparison of both revisions, ID 777 missed at t=100, then a different desktop ID appeared in the list. At t=100.1, with the banner rectangle covering the display, the baseline looked up the new ID and routed the event. The fix skipped the lookup and returned no target, so a move there would clear the fish's target and a click would lose its splash or bloom. An event at t=101.1 routed again. The same probe with a newly listed layer-0 window and a prior move's rectangle snapshot routed through that window on the fix, while the baseline resolved its ID and blocked it. Keep the bounded retry for a missing ID and cover events for a different, already-listed ID during the retry interval.

Known desktop and normal window IDs still take their cached routes, and 3,600 moves over resolved desktop IDs with the banner up took one window list read. Unresolved moves can still use the existing rectangle fallback, which can read once per 50 ms. The one-second limit covers verdict-list retries. A down that reaches the fallback still reads fresh rectangles.
