Brief `briefs/r1.md`, including the a2 addendum. Reviewed `origin/meadow-r1` at `a4f4ec7` against `971a216`. Status **changes requested**.

## Design

The passive local monitor closes the normal own-app delivery gap. Moves, drags and downs dispatched through AppKit's `sendEvent` reach the same router as foreign events. The local callback returns the original event on every path. Settings, About and ordinary alert events can reach the router, and listed own UI windows can now block it. App activation by itself does not determine the destination of a click on bare desktop. Menus, control tracking and window dragging can consume events in nested loops before the local monitor sees them. The common-mode display link can sample hover when it ticks in those loops. A down consumed there generates no wallpaper click. [Apple event monitoring guide](https://developer.apple.com/library/archive/documentation/Cocoa/Conceptual/EventOverview/MonitoringEvents/MonitoringEvents.html), [Apple local monitor reference](https://developer.apple.com/documentation/appkit/nsevent/addlocalmonitorforevents%28matching%3Ahandler%3A%29).

Both monitors run on the main thread, notifications use the main queue and the display links are on the main run loop. I found no cross-thread mutation in those paths. Window-list reads and habitat updates are synchronous. A local down can therefore delay the original event's delivery by the WindowServer call and simulation work even though it returns the same event. Keep that cost in the live measurements. [Apple event monitoring guide](https://developer.apple.com/library/archive/documentation/Cocoa/Conceptual/EventOverview/MonitoringEvents/MonitoringEvents.html).

An unreadable list produces `.unknown` for an eligible point, clears hover and suppresses clicks. The cached failure is retried on the next eligible down or once the hover refresh is due. The stationary retry also covers a foreign sheet, a banner or auto-hidden chrome appearing or disappearing without the pointer moving or the foreground app changing. The current observers miss those changes, so a bounded fallback poll is justified. A stable eligible point pays that read even on an empty desktop. At lower frame rates the synchronous read's individual latency matters alongside the average per second.

Display bounds use global point coordinates, with the same primary-height flip for AppKit samples and screen frames. Covered displays can be skipped even while another display remains live. Hidden Dock and menu bar have no hard-coded dead strips. Their eligibility depends on what WindowServer reports when they show or hide. AppKit occlusion is window-level and approximate, and the Space notification only dirties the cache. The checks do not establish that the on-screen list, wallpaper occlusion and display geometry agree during a full-screen or Space transition. [Apple occlusion state](https://developer.apple.com/documentation/appkit/nswindow/occlusionstate-swift.struct?changes=_9).

## What is missing?

- A supervised trace that matches each expected interaction with its callback, event coordinates, window hit and resulting wallpaper action. Use the report's scenarios and check window-interior clicks as well as exposed desktop, including a rounded corner or click-through surface, a stationary release after dragging a window away, and an own menu or control tracking loop. Switch Spaces with the pointer stationary. With two displays, cover one with a full-screen app and test the other. Repeat with the menu bar and Dock auto-hiding and with an offset or negative-origin display. The probe needs a known on-screen outcome for each case.
- The delivery checks encode AppKit's behavior in `PointerDelivery` and use `DesktopPointer.sources`, which the production installer does not read. Removing the local monitor, changing its mask, breaking the coordinate adapter or moving the display link out of common modes would leave those tests green. The checks do exercise the production router, parser, provider call counts and selected simulation calls. The nested-loop test supplies every tick itself, and the Meadow test verifies pointer presence and duplicate suppression without advancing a butterfly through dwell and landing. Preserve them as domain checks and cover the host boundary and actual dwell separately.
- The reported budget is a stable-layout fixture. Invalidations permit roughly ten reads per second plus clicks, and can reread screen geometry. The AppKit host samples cursor and button state before the shared throttle, once per active display callback. Two staggered links more than 8.3 ms apart can both get through. At 15 or 30 fps and after a delayed frame, one link callback can advance several 60 Hz simulation steps using a single sample. Document the real cadence, or move sampling to an explicitly shared input tick. Measure two staggered displays, a window being moved, and idle over both bare and blocked desktop. A window-list microbenchmark measures list and parse cost, with the main-thread overhead of host input and display callbacks outside its timing.

### New findings

- **Medium. Pending motion can bypass the new snapshot after a Space or window change.** Both invalidations clear the retained hint but leave `pending` in place. During an ordinary deferral, the router can also hold the pending event until the read. In a standalone probe using the production router, I queued a move with a desktop hit, put a foreign panel over that point while retaining the desktop window ID, and then invalidated. After the Space boundary, the first fresh read emitted `.moved` and the settle read still judged desktop. With an ordinary invalidation, the delayed read also judged desktop and emitted no leave. Discard pre-invalidation hover evidence and sample the current cursor after refresh. Add checks that queue the hit before the invalidation. The existing boundary fixture supplies a no-hit move after invalidation. See `PointerRouter.swift:335–352,401–436,490–499`.
- **Low. A move hint can keep a resting hover active for almost two seconds.** `hintLife` is one second, but expiry itself never schedules a rejudgment. A probe set a move hint 0.1 s after a list read. The first stationary refresh at 1.0 s retained the hint, and the router emitted `.left` at 2.0 s, 1.9 s after the hint was set. Rejudge at expiry using the cached list when no fetch is due, and assert expiry separately from the next periodic read. See `PointerRouter.swift:414–437,490–499`.
- **Medium. The default checks now require access to WindowServer.** `pointerLocalMonitorWithTheHostMask` unconditionally initializes `NSApplication.shared` before any screen check. Its synthetic events call `sendEvent` in-process and create no windows. That is suitable for an offscreen check in a GUI session. Apple documents that initializing `shared` connects to WindowServer, so the check cannot be assumed safe in a session without that access. The later `NSScreen` guard protects only the coordinate fixture. The CI job's `OCEAN_SKIP_GPU` setting does not guard this check. The hosted `macos-26` runner was not exercised by this review. Keep pure configuration and adapter assertions in the default suite and run the AppKit dispatch exercise in a job or probe with confirmed GUI-session access. See `PointerChecks.swift:857–901` and `.github/workflows/ci.yml:10–22`. [Apple's NSApplication.shared reference](https://developer.apple.com/documentation/appkit/nsapplication/shared).

### Coverage from the first review

- The host checks catch changes to the shared declarations when production continues to use them. Removing `.local` from `PointerHost.monitors`, dropping drags from `PointerHost.mask`, or breaking the flip in `PointerHost.location` reaches an assertion. The test registers its own monitor and feeds its own windowless events. `OceanChecks` depends only on `OceanKit`, so deleting the actual `.local` registration in `PointerMonitor.install`, changing its mask argument, bypassing its coordinate helper, breaking the local `e.window` path, or changing `DesktopWindows.swift:87` to default mode would leave these assertions green. This follows from the target graph and call sites. The report documents the live delivery, receiver and run-loop cases that cover these gaps.
- The cadence fixture measures deduplicated router work in rounded 60 Hz uptime buckets across staggered callback streams. The host still reads `NSEvent.mouseLocation` and `pressedMouseButtons` before that deduplication, once per display callback. At 15 and 30 fps the modeled cadence is one sample per callback, with multiple simulation advances possible per sample. The trace plan includes the requested popup, window-interior, rounded-corner, stationary-release, menu-tracking, Space, full-screen, auto-hide and offset-display cases.
