# Review m8: Offer the Meadow in the app

Brief: briefs/m8.md      Reviewed commit: df860b7

## Design

Request changes. The desk-wide allocation works on fresh two- and three-display layouts. The transition paths can exceed the cap, and a change on one display can reset the Web on another.

The three approved presets, Custom matching, the four switches, How many, and Speed are present. Settings decode old files with the existing Ocean and Web values intact. Unknown species names are dropped, known names are sorted and deduplicated, invalid field types fall back to defaults, and the count is clamped to 1–12. A line-up consisting of one species retains that species when sanitized, and the last switch is disabled. The desktop gates pointer input on Play with the pointer, and Meadow's settings also gate still-pointer landings. Speed uses the desktop clock, as the other habitats do.

I captured the app's Settings snapshots for Mixed and Custom in dark and light, and the native menu's outline for Ocean before trying Meadow, Meadow Mixed, and Meadow Custom. The Settings layout, swatches, selected and disabled states, capped count hint, and Fluttering · 30 fps match the approved design and subsequent decisions. The outline shows the native New badge in the pre-pick case, the three butterfly line-ups with ⌘1–⌘3 and their summaries, Your Line-Up in the Custom case, and Edit Line-Up…. I checked the submenu symbol in source. The menu snapshot serializes items, so it gives no evidence of their native rendering or keyboard dispatch. The welcome gets a Meadow chip through `HabitatKind.offered` before t9.

## What is missing?

The cap check filters out butterflies marked to leave, including those still on screen and creates fresh scenes for the multi-display cases. Add a transition check that goes through the scene host, exercises attach, detach, resize and count changes, and checks both the settled target and the butterflies still drawn during the transition. Include a held frame and a separate Web and Ocean scene whose own display geometry stays unchanged. The current count-change check only asserts an upper bound, so even an empty scene would pass that assertion.

### Builder rulings

- Moving the scene host into OceanKit is sound. App, bench and checks call `HabitatScene.arrange` with a desk that lives alongside the scenes. The host coordinate and sim ownership checks keep the app's existing scenes in place. The allocation regression below comes from polling the desk roster inside the simulation step.
- Accept the revised cap assertion. Twelve staying immediately would require eviction or let new butterflies spawn while the old ones still draw. The revised test samples total roster size through the transition and still requires exactly 12 at the destination with the outgoing species gone. The separate hosted transitions also assert the settled allocations, so an empty scene fails.
- Accept `arrival.v1` as a separate key and the shared eligibility rule for t9. Launch runs the Sharks hand-over before deciding arrival, and the hand-over's import guard checks `settings.v2` only. Recording a fresh arrival therefore leaves import eligibility intact. The 3.0.1 welcome writes `onboarded.v1` even if the user never changes a setting, which suffices to mark them as upgrading. A prior launch with no settings, onboarding marker or hand-over marker has the same available evidence as a fresh install.
