# Report r1: desktop pointer input, fixed at the cause (audit a1, finding 1)

Status: done with concerns
Board commit: 3173ba1 (brief r1 with the a2 addendum, on main)
Commit: b1c3b57 (the contract), on abc7d9a (the proof: the checks against a model of 971a216)

## The concerns, first

1. **What was proven offline is the contract, not AppKit.** `DesktopPointer` (pure, in OceanKit) holds every
   decision and is driven by 22 checks on a model desk. The desk's delivery rules (`PointerDelivery`) encode Apple's
   documented rules: a global monitor sees events dispatched to other apps, a local monitor sees the app's own events
   that pass through `sendEvent`, and neither sees a nested tracking loop. The host (`PointerMonitor`) builds and has
   been read through, but nothing ran it live (the rules forbid it here). The live trace below is how the manager
   and the director confirm it.
2. **"Failing on 971a216" means failing against a model of 971a216.** The 971a216 host cannot be driven offline, so
   commit abc7d9a holds a `DesktopPointer` that does exactly what 971a216's `PointerMonitor` did: one global monitor,
   the cursor at callback time, own windows ignored, any rectangle blocks, a failed list read as empty, a 50 ms cache
   kept across start and stop, no sample, one output per event. The same checks then run against the contract.
   The reviewer can compare that model with `git show 971a216:Sources/ASCIIAnimals/PointerMonitor.swift`.
3. **A resting pointer now costs a window-list read once a second; 971a216 read none.** That is how hover clears
   when a popup opens under a still pointer (Meadow landing included) and returns when it closes. It costs about
   1.3 ms a second on this Mac. A moving pointer costs a fifth of what it did (below).
4. **The click-through fix depends on one event field I could not observe.** The field is
   `mouseEventWindowUnderMousePointerThatCanHandleThisEvent`: the window the window server hands the event to. When
   an event names a window, the contract trusts it over the rectangles. When the event names none, the rectangle
   holds as before, a conservative approximation. The trace logs the field (`hit`) so the session shows whether
   macOS fills it for global and local events.

## The contract (`DesktopPointer`, the doc comment holds it too)

- **Sources:** a global monitor and a passive local monitor (it returns every event unchanged, so it never consumes
  one), both for moved, left-dragged and left-down. On top of them, a sample: the cursor and the left button, read
  once a simulation step from the display link, which runs in common modes (modal, event tracking). The sample
  never makes a click. A monitor that fails to install is logged in every copy.
- **Location:** the event's own location at event time (`cgEvent.location`; AppKit's when there is no CGEvent).
- **Moves** are coalesced: the newest one waits for the next step, before the scene advances. **Clicks** are judged
  at once at their own location, against a fresh window list.
- **Judging** goes through the windows front to back (on-screen, desktop elements listed). The first window wins
  when it is not click-through, has layer ≥ 0, has alpha ≥ 0.01 and its bounds hold the point. ASCII Animals' own
  windows block like any other. Its windows that take no mouse events never block: the habitats' desktop windows,
  and the welcome's dims over the other displays, known exactly from `NSApp.windows`. When the event names a window
  (the hit window), that verdict stands, and it is kept for samples at that same point while the same windows cover
  it. A point on a covered screen, or in no screen, is off the desktop and needs no window list. An unreadable list
  routes nothing (`unknown`) and is read again later.
- **Gesture ownership:** a left-button gesture that began off the desktop owns its drags until the button comes up
  (the sample reads the button, so a missed up cannot latch it).
- **Freshness:** the screens and the window list are dropped on start, stop and `invalidate`. The host invalidates
  on: own windows becoming key or not, closing, moving, resizing or changing occlusion; menu tracking beginning or
  ending; the app becoming active or inactive; a Space change; another app activating, hiding or unhiding; and every
  director `updatePointer` (mode, visibility, displays, settings). After an invalidation the pointer is judged again
  and told again (a fresh scene learns a still pointer; the habitats take a repeat as a no-op).
- **Only changes are told:** one `moved` per new target, one `left`. The pointer runs only while a habitat is live,
  interaction is on and some screen is exposed. Otherwise no monitor is installed.
- **No new permission:** window bounds, layers, alpha and PIDs only (no names); no Accessibility, Input Monitoring or
  Screen Recording.

## Cost per step (the a2 addendum)

- **Window-list reads:** a burst of 240 moves in 2 s (120 Hz) over windows went from **40 reads and 240 screen
  reads** before to **8 reads and 1 screen read** after. A resting pointer on bare desktop: 59 reads a minute
  (0 before). A covered screen: 0 (15 before for 120 moves). Clicks: exactly one read each, at once (both).
- **Bounds:** at most one read per `moveLife` (0.25 s) while moving, per `stillLife` (1 s) at rest and per
  `minRefetch` (0.1 s) after invalidations, plus one per click. So ≤ 10 reads a second outside clicks.
- **Read cost on this Mac** (`pointerWindowListCost`: `CGWindowListCopyWindowInfo` plus parsing, the same call the
  host makes): 1.15 to 1.42 ms each over five runs, with 20 to 25 windows. While moving that is about 5 ms a second
  now, against about 26 ms before (20 reads a second). At rest it is about 1.3 ms a second.
- **A step with nothing new** costs one `NSEvent.mouseLocation`, one `pressedMouseButtons` and a few compares. It
  reads no list, allocates nothing and tells no habitat.

## Live trace for the manager (not run by me)

The trace is on the energy-test copy only: `ASCII_ANIMALS_POINTER_TRACE=1`, and no `--snapshot-*` flag. Lines go
to the copy's log, `build/energy-test/app/ascii-animals.log`:
- `pointer trace: start; global monitor on|MISSING, local monitor on|MISSING`
- for every click and every change of route: `pointer <global|local|sample> <move|drag|down|sample> at (x, y) mode
  <run-loop mode> hit <window|-> -> <desktop display N (x, y) | blocked by window W pid P [(own)] layer L alpha A
  rect R | a drag owned by a window | off the exposed desktop | unknown> read <yes|no> told [...] frames <n>`
- once a second: `pointer 1s: global G local L judged J reads R frames F`

How to read it: if the global and local counts stay 0 while the samples show the moves, the callback is missing
(delivery). A `blocked by window …` over bare desktop means a rectangle refused it, and the line names the window.
`hit` shows whether macOS names the receiving window. `frames` rising shows the animals kept moving.

## Rulings

- **Own windows that take no mouse events pass through** (the welcome's dims at alpha 0.55 over the other
  displays). Brief and audit say own UI windows block. The dims are not UI, and AppKit says exactly which windows
  ignore the mouse. If this is wrong, the dimmed displays react under the welcome, as they did before.
- **Gesture ownership** is in, from the audit's "Fix and proof". The brief's list leaves it out. It is small,
  needs no window list for those drags, and stops a window drag from stirring the habitat underneath. If wrong:
  a drag from a window onto the desktop no longer stirs the habitat until the button comes up.
- **The trace logs changes, not every move.** It logs every click and every change of route, plus a per-second count
  per source. Logging every 120 Hz move would roll the 512 KB log within a minute and lose the session's start.
- **The window list now includes desktop elements** (no `.excludeDesktopElements`), so a hit window that is the
  Finder's desktop can be recognised. They never block (layer < 0). That costs a few more entries per read, and the
  read cost above includes them.
- **The lives**: 0.25 s moving, 1 s resting, 0.1 s after invalidation. While moving, a window that has just opened
  can be missed for up to 0.25 s (it was 0.05 s). Clicks are unaffected.
- **The proof commit abc7d9a fails checks on purpose** (14 at the time; 15 with the final checks). It is not meant to
  merge on its own. Squash it if CI on every commit matters.
