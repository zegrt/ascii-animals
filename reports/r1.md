# Report r1: desktop pointer input

Branch `meadow-r1b`, from `meadow-t11` @ 971a216. The earlier build (`meadow-r1` @ 3a5a7a8) and its report stay on
`meadow-r1` for reference; this branch is the brief's right-size and nothing from that build's snapshot, hint, queue,
generation or local-monitor machinery.

## Right-size

**The cause, seen live** (board Corrections, 2026-11-21): while a notification banner shows, Notification Center puts
a window over the whole built-in screen (layer 21, alpha 1, the display's full frame). 971a216 judged every pointer
event by window rectangles, so that window counted as covering the desktop and the fish ignored the pointer on that
screen until the banner went. The pointer callbacks never stopped.

**The rule** (`PointerMonitor.handle`, `PointerRouter.route(_:eventWindow:occluders:viewports:)`): each move, drag and
click takes the window the window server handed it to (the event's
`mouseEventWindowUnderMousePointerThatCanHandleThisEvent`, the field 3a5a7a8 used live).
- a desktop-level window (layer below 0: the Finder's desktop, the system wallpaper, our own habitat windows):
  the point goes to the fish on the screen under it, whatever the list has over it;
- any other window (an app's window, the banner itself when it is clicked): blocked;
- no window number, or a number not in the window list: today's rectangles, as 971a216.

**Cheap by design** (`EventWindowVerdicts`): each window number's verdict (its listed layer) is kept in a map. The list
is read only for a number not seen before, and that one read fills the map for every listed window; the map is
cleared when the pointer starts and on a Space change (`NSWorkspace.activeSpaceDidChangeNotification`) or a display
change (`didChangeScreenParametersNotification`), and starts again past 512 entries. An event with no window number
reads nothing new (the rectangles keep 971a216's 50 ms cache, fresh for a click). No still-pointer sampling.

**List reads for a minute of moving over the desktop** (offscreen, fake list, banner up, 60 moves a second handed to
the Finder's desktop and our habitat in turn): **1 read for 3,600 moves**. 971a216 read the list up to 20 times a
second while the pointer moved (up to 1,200 a minute), and fresh on every click.

**The checks** (`Sources/OceanChecks/PointerChecks.swift`). Proof commit 7787b73 adds them with the API behaving as
971a216 (rectangles always, a list read per look): 6 of 7 fail.

```
FAIL pointerBannerWindowDoesNotHideTheDesktop: event to the Finder's desktop with the banner up: nil
FAIL pointerAnyOtherEventWindowBlocks: event to the banner's window: Optional(...(viewportID: 0, local: (1200.0, 900.0)))
FAIL pointerNoEventWindowFallsBackToRectangles: no window number needs no list read: 4
FAIL pointerUnlistedEventWindowFallsBackToRectanglesOnce: one read for an unseen number, then the map: 3
FAIL pointerDesktopMinuteReadsTheListOnce: routed 0 of 3600
FAIL pointerSpaceOrDisplayChangeForgetsVerdicts: before
PASS pointerListedWindowParsesTheWindowList
```

Fix commit b34a20b: all 7 pass.
- `pointerBannerWindowDoesNotHideTheDesktop`: a banner-sized layer-21 window in the list; the event's window the
  Finder's desktop or our habitat: routed to the point.
- `pointerAnyOtherEventWindowBlocks`: the event's window an app window, or the banner's: blocked.
- `pointerNoEventWindowFallsBackToRectangles`: no number: the rectangles exactly as before (blocked by the banner's
  rectangle, by a window's, routed on bare desktop and on the other display), and no list read.
- `pointerUnlistedEventWindowFallsBackToRectanglesOnce`: a number not in the list: rectangles, one read, then the map.
- `pointerDesktopMinuteReadsTheListOnce`: the minute above: 3,600 routed, 1 read.
- `pointerSpaceOrDisplayChangeForgetsVerdicts`: a verdict is kept with no read until `clear`, then read again.
- `pointerListedWindowParsesTheWindowList`: the window list's dictionaries to number and layer.

**Runs on b34a20b:** `swift build` clean; `swift run -c release OceanChecks`: 287 passed, 0 failed (280 + 7 new);
`ENERGY_DRY=1 bash Tools/energy.sh selftest`: 0 failed; `Tools/build.sh --test` built `build/ASCII Animals Test.app`
(not launched).

**The trace for the live re-run** (energy-test copy only): `ASCII_ANIMALS_POINTER_TRACE=1` writes one line per event
to `pointer-trace.log` beside the copy's log (at most 16 MB a run), e.g.
`8123.456 move window 120 layer -2147483603 verdict desktop at 1200,900 -> screen 0`. With a banner up, moves over the
desktop should read `verdict desktop ... -> screen N`; over an app window `verdict window ... -> none`.

**Not checked offline:** what the window server puts in the event's window field for each case (the live trace with
3a5a7a8 showed it for the banner); the install and the notifications in `PointerMonitor`, as OceanChecks links only
OceanKit. Everything else keeps 971a216's behaviour: the global monitor only, the cursor position at callback time,
own windows not in the rectangles.
