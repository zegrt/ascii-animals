Rulings:
- Order with the Web card: a Sharks user arriving at 3.1 is an upgrade by `Arrival`, so both cards are due. The Web
  card shows first (unchanged), the Meadow card on the next launch, so only one card shows at a time. If wrong:
  that person sees the Meadow card one launch later than other upgraders.
- "Never takes the keyboard": the panel never becomes key (non-activating, `canBecomeKey` false), so Esc can only
  reach it while ASCII Animals is the active app (a local key monitor); a global key monitor would need
  Accessibility/Input Monitoring and could raise a permission dialog. A click anywhere else (global and local mouse
  monitors, which need no permission) always closes it, and "esc close" is itself a button. If wrong: someone typing
  in another app can't dismiss it with Esc, only with a click.
- "Shown" is marked when the card goes on screen, and the card waits until the screen is awake, unlocked and not
  behind the screen saver (an automatic update can relaunch the app at night). If there is no renderer the card
  isn't shown or marked, and tries again next launch, as the welcome does.
- The tour marks the Meadow card seen too (its first beat offers the Meadow), as it already does for the Web card.
- In the welcome, picking a Meadow line-up updates the scene in place (`sim.update`, the desktop's way: spares fly
  off, newcomers fly in) rather than rebuilding it; `LiveOceanView.rebuild` ignores Meadow line-up changes.
- The card's Meadow is live at desktop scale (zoom 1); a still in Low Power Mode, as the design says. Reduce Motion
  only skips the typing and shortens the fades.
- The card closes when the Meadow is picked elsewhere while it is up (menu, Settings), when the welcome tour opens,
  or when displays change; all keep the habitat.
