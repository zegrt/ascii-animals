## How the proof works

moves them unchanged into OceanKit's `UpdateEngine`, behind an `UpdateHost` protocol (clock, preferences, the app's
surfaces, feed, download, swap, restart, notifications, alerts); `UpdateService` becomes that host and is wired to
it, and `SelfUpdater.install` is split into `stage` (download and checks), `commit` (the rename) and
`scheduleRelaunch`, still run back to back. Report a Problem goes through `IssueReport.form`, which in the proof
commit still returns today's full body. So the proof commit is 971a216's behaviour behind a seam, and the checks
drive it with fakes (`Sources/OceanChecks/UpdateChecks.swift`: a dictionary store, a fake host with a queued feed,
download and notification centre, a settable clock and surfaces).

## Causes and fixes, per kept item

1. **An update never replaces the app under the user.** Cause: "busy" was `NSApp.isActive` only; an unfocused
   Settings window, an open menu, the non-activating card or the welcome don't make the app active. A release
   found earlier took the automatic path at launch, before the welcome. The download-and-swap ran as one step with
   no second look. Fix: `UpdateSurfaces` (app active, a window of its own up, a menu open; `busy` is any), read by
   `UpdateService.surfaces` from the app's real state each time: `NSApp.isActive`; `NSApp.modalWindow`,
   `OnboardingController.isShowing`, or any visible window of the app at normal level or above that isn't the
   menu-bar icon's (`NSStatusBar…` class), which covers Settings focused or not, About, the welcome and the card's
   panel, while the wallpaper windows (desktop level) don't count; a menu open from `NSMenu`'s begin/end tracking
   notifications or the main run loop in event-tracking mode. No file outside the brief was edited for this. At
   launch a cached release is only shown; the first tick decides. After the download the engine looks again
   (checks on, automatic installs on, re-read; not busy; not a failed tag): if anything says no, the download is
   discarded and the release waits for a later tick. Asked-for installs (menu, notice, Check for Updates) go ahead
   regardless.
2. **"You're up to date" only after a valid check.** Cause: every answer, including a failure, set the last-check
   date (so the next try was 20 h away), and a 200 that didn't parse was cached and read as "nothing newer". Fix:
   `UpdateFeed.read` tells a release, a readable answer with nothing to install, and garbled apart. Only a readable
   answer is cached and sets the last-check date; garbled, a transport failure, a non-200/304 or a 304 with nothing
   readable kept is a failure: "Couldn't check for updates" when asked, and the next hourly tick tries again.
3. **A relaunch that can't start doesn't quit.** Cause: `SelfUpdater.relaunch` logged a failed `Process.run` and
   called `NSApp.terminate` anyway. Fix: `scheduleRelaunch` returns whether the helper started; the engine quits
   only then. Otherwise the old copy keeps running, says "ASCII Animals 3.x is installed. It couldn't restart by
   itself, so this copy keeps running. Quit ASCII Animals and open it again to finish.", and doesn't download the
   same release again (a later Check for Updates repeats that message).
4. **No crash from a stored setting.** Cause: `Settings.sanitized` subtracted the decoded fps before bounding it.
   Fix: clamp to 0…1000 first. Checks: `Int.min`, `Int.min + 1`, `Int.max`, -1, 0 through `SettingsCodec.decode`
   and `sanitized()`, plus 3.0's and ASCII Sharks' saved settings round-tripping.
5. **Report a Problem sends nothing unseen.** Cause: the menu item opened a GitHub URL with the diagnostics in its
   query, so they left the Mac when the browser loaded it, before anyone read them; it carried display names, the
   Mac model and the raw log, redacted only for the exact home path and short name; and the URL builder cut the
   text after it was built. Fix: `Diagnostics.review` shows a local alert with exactly the text that will go into
   the form, read-only, with "Add the recent log (your folders and names are taken out)" unticked; only "Open
   GitHub Form" opens the URL, with that same text. `IssueReport.form` holds the allowlist (app version, macOS,
   display count and sizes, settings), adds the log only when chosen, in a fence no log line can close, removes the
   home folder, the short and full names, other accounts' folders (`/Users/<user>`) and volume names
   (`/Volumes/<volume>`), and returns text already cut to fit the link, so the URL carries it unchanged
   (`reportShownIsSent`). Copy Diagnostics stays the fuller local copy; it now uses the same redaction.
6. **No update timers while checks are off.** Cause: `start` armed the 30 s first look and the hourly timer
   regardless. Fix: the engine arms them only while checks are on, and re-arms or stops them on a settings change
   (`SettingsStore` posts `SettingsStore.didChange`; `UpdateService` listens, so `main.swift`'s `settingsChanged`
   wasn't touched). The first look is now a cancellable timer. Check for Updates works with checks off.

## The signing note (docs/DEVELOPING.md, Known limits)

> **Signing:** the app is signed ad hoc, not with a Developer ID. That's why macOS asks for Open Anyway the first
> time. It also limits what a self-update can prove: the checksum comes from the same GitHub release as the
> download, and an ad hoc signature shows the app is intact, not who made it. So an update is as trustworthy as the
> GitHub repository and its releases; it is not separately authenticated as ours. Developer ID signing (or a
> separately signed release manifest) would close that, and is not planned for 3.1.

The Updates paragraph also says, in a sentence, when an automatic update waits and what a failed check or restart
does. The checksum, identifier, version and signature checks are unchanged.
