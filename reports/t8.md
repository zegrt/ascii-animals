**How to stop at any point.**
- **Ctrl-C** in the Terminal: `interrupted; cleaning up`, then the test copy is quit (identity checked first), the test
  domain deleted (verified), the scratch removed and the lock released; exit 130. A second Ctrl-C is ignored until
  that is done. If cleanup cannot confirm a step it says which, and exits 1.
- **The Terminal was closed** (or its output went away): the same cleanup runs (exit 129). Check with
  `Tools/energy.sh status` from a new Terminal.
- **The run was killed outright** (`kill -9`, a crash): the lock stays behind with a dead owner and every run stops at
  it. `Tools/energy.sh status` shows `lock: dead (...)` and what else is left; `Tools/energy.sh recover` quits this
  checkout's test copy, deletes the test domain, removes the scratch and clears the dead lock.
- **If `recover` fails**, by what it says:
  - `a test copy not from this checkout is running`: quit it from its own menu (the one that starts with
    "ASCII Animals Test"), then `recover` again.
  - `the test copy is still running`: Activity Monitor, search "ASCII Animals Test", select only that, Quit; then
    `recover` again.
  - `test domain ... not verified deleted`: never a bare `defaults delete`. Run `Tools/energy.sh status` (it must show
    `lock: free` and `test copy running: none`), then `Tools/energy.sh recover` again: it takes the lock, checks for
    the test copy and deletes the domain, verified. If it still cannot, stop there and note it: the test domain
    holds only the test copy's own settings, nothing of the director's, and is dealt with after the session.
  - `another run holds the lock (... held ...)`: a run is still going (its pid is printed); finish or Ctrl-C it in
    its Terminal. `starting`: a run is starting; wait a few seconds and try again.
  - `missing build/ASCII Animals Test.app`: rebuild it (`Tools/build.sh --test`), then `recover` again.
  - `refused: build/energy-test is a symbolic link` (or `build`, or something inside it): every mode refuses, recover
    and status too. Stop: someone made that link, and it is looked at after the session, not removed in a hurry.
  None of these touch the director's apps, settings or wallpaper.
- The director can also quit the test copy from its menu; a run in progress then reports itself invalid and cleans up.
- A dialog appears: none is expected from the test copy (no updater, hand-over, uninstall, notification or Apple
  Events). If one does, the director reads it before answering, and we stop and note it.

**What this promises, and what it doesn't.**
- Holds (checked below): energy.sh refuses the real and Sharks domains and IDs in any spelling; writes only the test

  copy runs. The test copy never runs the updater, hand-over, uninstaller, system-wallpaper match or login item, and

  `build/energy-test` (or what energy.sh makes in it) is a symbolic link.

  after `defaults delete`, a LaunchServices registration (so "ASCII Animals Test" can show in Spotlight), and possibly

- The director's quit and reopen of their own apps have those apps' ordinary effects (wallpaper put back on quit if
  matching is on; their update check on open, as they have set it). That is an ordinary user action, not the script's.
- Not proven before the session, because nothing live was run: the test copy launched by `open --env` (with its
  launch id reaching it), its plan and readings logged from a live desktop, the 3 s wallpaper-app look running beside
  `top` without disturbing the minute, `lsof` and `lsappinfo` on it, `top` on it, the card's live "on screen" line.

**Accepted residual risks** (the manager's routing of re-check 2: the session is one supervised run with the director
present and the manager typing the commands; these are not guarded against in code):
- **One operator only.** The lock is per checkout and its stale-lock recovery is not safe against a second person
  running `recover` or a run from another checkout at the same moment. Only the manager types energy.sh commands, in
  one Terminal, from one checkout.
- **PID reuse.** Signals go to a bare pid after its identity (kernel executable path, bundle ID, start time to the
  second) is checked; macOS reusing that pid for another process within that instant is not excluded.
- **A launch that never registers.** If `open` returns but the test copy has not registered when the waits end,
  cleanup finds no test copy and reports success. So the manager runs `Tools/energy.sh status` after the last run,
  and the director reopens their apps only once it shows `test copy running: none`.
- Also left (the routing's other cases): filesystem tricks beyond the symlink pre-check (a hard link, a link made
  after the check), and display changes shorter than the 5 s between readings.

## Rulings
1. **The director's apps are found three ways** (LaunchServices bundle ID, a running bundle's Info.plist, the
   executable names `ASCIIAnimals` and `ASCIISharks`). This is broad on purpose: a dev binary or a `--snapshot-*` run
   of the real app also blocks a live run until it ends. If wrong: the manager waits for it to finish.
2. **Low Power Mode for the baseline comes from `pmset`**: this Mac shows `powermode` (1 is Low Power) under
   "Currently in use"; older systems show `lowpowermode`. If neither shows, the run is invalid ("unknown") rather
   than assumed off. Measure runs also need the test copy's own reading (`ProcessInfo`) to say off.
3. **A display counts as at the asked rate within 15 %** in every 5 s reading (25.5-34.5 at 30, 12.75-17.25 at 15),
   and a run's readings must have no gap over 7 s and cover its window. If too strict on the ultrawide: a run fails
   and says which display and when.
4. **The lock is per checkout** (under its `build/`), as the brief asks. Runs from two checkouts at once are still
   kept apart: any test copy running from anywhere stops a live run, and a dry run never deletes the test copy's own
   domain while one runs.
5. **The test copy's log and crash marker moved into `build/energy-test/app`** (from `~/Library/Logs` and
   `~/Library/Application Support`), so all its files are in the one folder and energy.sh reads the log at a fixed
   path. Nothing was ever created at the old places on this Mac (checked absent).
6. **Seconds are 20-600** for live runs (a reading comes every 5 s; fewer than 20 s cannot be checked).
7. **Calibration takes the count the test copy shows**, read from its reading after the director's answer, not from
   the domain after quitting. The two must agree, or it asks again.
8. **energy.sh keeps `build/energy-test/results.log`** (one line per run, with the commit) and the test copy's log
   between runs; `run/` is removed at the end of each. `build/` is ignored by git.
9. **The identity probe makes two links inside `build/energy-test`** to test link escapes, and removes them.
