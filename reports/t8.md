## Rewrite (2026-11-21, after the safety review)

Nothing of the owner's is saved and restored any more, because nothing of the owner's is written. The session runs a
separate copy of the app, and `Tools/energy.sh` drives only that copy.

**The test identity.** `Tools/build.sh --test` builds `build/ASCII Animals Test.app`: bundle ID
`local.ascii-animals.energy-test`, name "ASCII Animals Test", executable `ASCIIAnimalsEnergyTest`. macOS keys
`UserDefaults.standard` by bundle ID, so its settings live in the domain `local.ascii-animals.energy-test`. Its log is
in `~/Library/Logs/ASCII Animals Energy Test`, its crash marker in `~/Library/Application Support/ASCII Animals Energy
Test`. `AppIdentity(bundleID:)` decides from the exact ID alone (the real ID, any other spelling or a bare binary never
takes the test path), and `LaunchPlan` turns that into what the launch may do. In the test copy:

| Never | How (each guarded where it acts, so every way in is closed) | Proof |
|---|---|---|
| Self-updater, update checks | `updates.start` not called; `UpdateService` start, checkNow, install and auto-install return at once; `SelfUpdater` blocker, install and relaunch refuse; the menu has no "Check for Updates" | probe: no check scheduled, no request, install refused "by the identity" |
| Sharks hand-over and watcher | `LaunchPlan.runsHandover` is false (whatever the environment) | probe: hand-over off, watcher never started; checks |
| Uninstaller | `Uninstaller.confirm` answers no without asking, `run` refuses, `--uninstall` exits 1, the Help item is gone | probe: no dialog, the bundle stays |
| System wallpaper, `wallpaperMemory.v1`, stills | `SystemWallpaper(renderer:)` returns nil before reading or making anything; "Restore Original Wallpaper" is gone | probe: never made; `wallpaperMemory.v1` absent |
| Login item | `LoginItem.set` throws; "Open at Login" is gone from the menu | probe: refused |
| The owner's log, crash marker, defaults | own folders and own domain | probe and checks |

Its developer modes, honoured by the test copy only (the app people install ignores all three flags):
quiet by default (no welcome, no card, `arrival.v1` neither read nor saved); `ASCII_ANIMALS_PREVIEW_WHATSNEW=1`
shows the what's-new card once over the app's defaults held in memory (nothing read from or written to any domain);
`ASCII_ANIMALS_BUILTIN_DISPLAY_ONLY=1` draws on the built-in display alone. Both preview and quiet set: quiet wins.
Every 5 s it logs `energy: mode=live30 fps=29.8 screens=2 ...`: the power mode and the frames actually drawn per
second per screen, which energy.sh reads. Its menu starts with "ASCII Animals Test: energy test copy".

**`Tools/energy.sh`** now has `baseline`, `<habitat> <fps> [seconds] [count]`, `preview`, `calibrate [count]`,
`status` and `recover`:
- Only the test copy: it checks the bundle's ID is exactly the test ID, its executable is `ASCIIAnimalsEnergyTest`
  and the signature verifies, and refuses the real ID or Sharks' in any spelling (case, spaces, folders, `.plist`).
  The domain override is a dry-run hook only, limited to `local.ascii-animals.energy-test[.<word>]`.
- Every run deletes the test domain, writes it for this run (habitat, fps, count; wallpaper match and update checks
  off), reads it back (type and bytes), and deletes it at the end, verified absent.
- One run at a time: the run holds `lockf` on one per-user lock file until it exits (released even if it is killed),
  whatever checkout it is started from.
- The owner's apps: found by the bundle ID in the Info.plist of each running app's bundle; their bundle paths are
  recorded in a file before anything is quit; quit with SIGTERM (no Apple Events, so no Automation prompt), waited for;
  relaunched at the end from the recorded path (ASCII Animals with `ASCII_ANIMALS_NO_HANDOVER=1`), and the relaunch
  verified by its process. Nothing is relaunched until the test copy is confirmed gone. `recover` finishes a killed
  run from the record.
- Sampling: `top` on the exact test pid and WindowServer pid; it needs the full series, and both rows in every
  sample, or the run is invalid. The actual frame rate and power mode for the sampled minute come from the test copy's
  log; a run not live at the asked rate (heat, Low Power, a covered screen) is marked invalid. A dry baseline is refused.
- Cleanup runs on exit, error and Ctrl-C, ignores further Ctrl-C until done, and a failed cleanup fails the run.

## Session runbook

Everything is run by the manager from the root of a checkout at the commit being measured, in Terminal. The
director watches and does what each step says. Nothing here writes the director's settings, wallpaper or apps; the
only thing to put back is their own ASCII Animals, which energy.sh relaunches (or `recover` does).

**Before (about 5 minutes)**
1. `Tools/build.sh --test` (a few minutes: checks, then two architectures). The last line must read
   `built build/ASCII Animals Test.app: local.ascii-animals.energy-test, ASCIIAnimalsEnergyTest (x86_64 arm64), from
   <the commit>` with no `+ uncommitted changes`. That names the build's provenance.
2. `Tools/energy.sh status` (changes nothing): lock free, nothing to relaunch, test domain absent, no test copy
   running. It also lists the director's running ASCII Animals or ASCII Sharks.
3. The director: plugged in, Low Power Mode off, every window closed or minimised so the desktop is uncovered on
   both displays, no screen saver due. Optional: quit their own ASCII Animals from its menu now (it puts their
   wallpaper back); otherwise energy.sh quits it before each run and relaunches it after, so it comes and goes
   between runs.
4. The manager notes the displays for the table (read-only):
   `system_profiler SPDisplaysDataType | grep -E "Display Type|Resolution|UI Looks like|Main Display"`.
   Expected (board): the built-in at 1800 x 1169 pt at 2x (main) plus the LG ultrawide at 3440 x 1440 pt at 1x.

**The Meadow's count by eye (about 3 to 5 minutes)**
5. `Tools/energy.sh calibrate` (or `calibrate <n>` to start from a count). The test copy shows the Meadow on the
   built-in display alone; the ultrawide shows the director's own wallpaper. The director clicks the fish icon whose
   menu starts with "ASCII Animals Test: energy test copy", opens Settings and moves **How many** until the laptop
   screen feels like the sketch, then says so. The manager presses Return. energy.sh quits the test copy, prints
   `count chosen: <n>`, deletes the test domain and relaunches the director's app. Note the count in the table. It
   is not saved anywhere else.

**Energy (7 runs, about 90 s each)**
Each run: quits the director's apps (recorded), writes the test domain, opens the test copy quietly, settles 10 s,
samples 60 s, quits it, deletes the test domain and relaunches the director's apps.
**The director does not touch the Mac, nor move the pointer, from Return until the prompt comes back.** The Meadow
and the Ocean react to the pointer.

6. `Tools/energy.sh baseline`
7. `Tools/energy.sh ocean 30`
8. `Tools/energy.sh web 30`
9. `Tools/energy.sh meadow 30 60 <count>`
10. `Tools/energy.sh ocean 15`
11. `Tools/energy.sh web 15`
12. `Tools/energy.sh meadow 15 60 <count>`

After each, check: `actual frame rate` close to the asked rate and `power mode: live30 xN` (or `live15`); no `NOTE`
lines and no `invalid`; `test domain ... deleted (verified absent)`; `ASCII Animals relaunched and running` if it was
running. An invalid run exits non-zero: clear the cause (a covered desktop, Low Power, heat) and run it again.
The habitat's looks are the app's defaults (only habitat, fps and count are set), not the director's own.
Optional: `Tools/energy.sh baseline` again at the end, to see whether WindowServer drifted.

**The what's-new card, live (about 2 minutes)**
13. `Tools/energy.sh preview`. About a second after the test copy opens, the card fades in under its fish icon
    (top right of the main display), with the Meadow live in it, as an upgrader on the Ocean sees it. It reads and
    saves nothing. "Try the Meadow", "Keep the Ocean" and Esc only close it. **A click outside closes it and also
    reaches whatever was clicked** (the desktop, another app). It shows once per launch; run the step again to see it
    again. When done, the manager presses Return: the test copy quits and the director's app comes back.

**After (1 minute)**
14. `Tools/energy.sh status`: lock free, nothing to relaunch, test domain absent, no test copy running, and the
    director's ASCII Animals running if it was at the start.

Total: about 25 minutes.

**How to stop at any point.**
- **Ctrl-C** in the Terminal: it prints `interrupted; cleaning up`, quits the test copy, deletes the test domain and
  relaunches the director's apps. A second Ctrl-C is ignored until that is done.
- The Terminal was closed or the run killed: `Tools/energy.sh status`, then `Tools/energy.sh recover` (quits any
  test copy, deletes the test domain, relaunches what the run had quit, from its record).
- The director can also quit the test copy from its own menu ("Quit ASCII Animals" in the menu that starts with
  "ASCII Animals Test"). A run in progress then reports itself invalid and cleans up.
- Nothing to restore: the director's settings, wallpaper and installed apps were never written.
- A dialog appears: none is expected (no updater, no hand-over, no uninstall, no notification, no Apple Events). If
  one does, the director reads it before answering, and we stop and note it.

## Rulings
1. **The developer flags work in the test copy only.** The real app ignores `ASCII_ANIMALS_QUIET_LAUNCH`,
   `ASCII_ANIMALS_PREVIEW_WHATSNEW` and `ASCII_ANIMALS_BUILTIN_DISPLAY_ONLY` (the first round's quiet and preview paths
   in the real app are gone). If wrong: one condition in `LaunchPlan.init`.
2. **The test copy is quiet when launched with no flag** (opened from Finder, say): no welcome, no card. If wrong: it
   would show the welcome and write it to its own domain only.
3. **The test copy hides Check for Updates, Restore Original Wallpaper, Open at Login, Welcome Tour and Uninstall**
   from its menu. Its Settings window still shows the update, login and wallpaper toggles; they do nothing (Open at
   Login shows "The energy-test copy doesn't open at login." inline, no dialog). If wrong: hide them in SettingsView.
4. **Measurements use the app's default looks**, with only habitat, fps and the Meadow's count set; the director's own
   settings are not read. If wrong: the numbers may differ from the director's own look (appearance, grid, line-ups).
5. **The director's ASCII Animals is relaunched with `ASCII_ANIMALS_NO_HANDOVER=1`** (the project rule for any
   launch), so its Sharks watcher is off until its next ordinary launch (login). Quitting it before the session
   (step 3) avoids that and avoids it coming and going between runs.
6. **Apps are quit with SIGTERM** (as `Tools/install.sh` does), not Apple Events, which can raise an Automation
   prompt. ASCII Animals quits normally on it and puts the wallpaper back (its `main.swift`). That ASCII Sharks does
   the same is assumed from the shared code, not checked; if it does not quit in 15 s, the run stops before changing
   anything and relaunches what it had quit.
7. **The lock is a file in the user's `$TMPDIR`** held with `lockf`, so it is one per user whatever checkout runs.
8. **energy.sh leaves the test copy's log** (it holds the frame-rate record) and its crash-marker folder; it deletes
   only the test domain. Both folders are the test copy's own.
9. **energy.sh refuses any domain or ID containing "wallpaper"**, besides the exact real and Sharks IDs.
