## Objective
The director will sit with the manager for a live energy session on their Mac (plugged in, Low Power Mode off,
desktop clear): baseline, then Ocean, Web and Meadow at 30 and 15 fps, 60 s each, with `Tools/energy.sh`, and see the
what's-new card live. The display setup has changed since the old table, so every habitat is measured again in the
same session. Prepare everything so the session is short and safe. Nothing in this task runs live.

## Do
1. **`Tools/energy.sh` measures the Meadow:** `meadow` as a habitat (same settings save, backup and restore; the
   Meadow's settings fields left at the director's defaults). Run its existing dry-run test hooks
   (`ENERGY_DOMAIN=<throwaway>`, `ENERGY_DRY=1`) to prove the save, modify and restore for `meadow`, never on the real
   domain.
2. **A safe live preview of the what's-new card:** a developer flag (for example
   `ASCII_ANIMALS_PREVIEW_WHATSNEW=1`) that shows the card on the real desktop once, as an upgrader would see it,
   without reading or writing the once-only flag, `arrival.v1` or any setting, and without the hand-over; "Try the
   Meadow" and "Keep" only close the card in this mode. Check it offscreen with the existing probe.
3. **A session runbook** in `reports/t8.md`: the exact commands in order, how long each takes, what the director
   does (clear the desktop, not touch the Mac during a run), how settings are restored, how to stop at any point,
   and a results table to fill in (app CPU, WindowServer added, memory) with the display setup noted.
4. **Build the app bundle** with `Tools/build.sh` (checks included) so `build/ASCII Animals.app` is this branch.
   Do not install it, launch it or run `energy.sh` for real.

## Rewrite (2026-11-21, after the safety review)
Read `git show origin/review-t8:reviews/t8.md` and the board's routing (Review routing, t8 prep). The review showed
that saving and restoring the owner's real settings can't cover what a live launch touches (the updater, the system
wallpaper, `wallpaperMemory.v1`, the crash marker and logs, the Sharks hand-over, the uninstall menu). So the session
runs a **separate test identity** of the app and never touches the owner's real state.

1. **A test identity.** `Tools/build.sh` (or a new `Tools/build-test.sh`) can produce `build/ASCII Animals Test.app`
   with its own bundle ID (for example `local.ascii-animals.energy-test`), name, executable name, defaults domain,
   log folder and crash marker. In that identity the app never starts the self-updater or update checks, never runs
   the Sharks hand-over or its watcher, never offers or runs the uninstaller, never matches or changes the system
   wallpaper, and never writes `wallpaperMemory.v1`. Decide these from the bundle ID in one place, so the real app
   can't take that path. Prove each with checks or offscreen probes.
2. **`Tools/energy.sh` drives only the test identity** and only its own defaults domain: it writes the test
   domain's settings for each run (habitat, fps, the Meadow's count) and deletes the test domain at the end; it
   refuses to run against the real bundle ID or domain in any spelling. No backup of the owner's settings exists
   because nothing of the owner's is written. One run at a time (a lock). Sampling validates a full series for the
   exact test process and WindowServer, rejects missing rows, and reports the app's actual frame rate and power mode.
   The owner's installed ASCII Animals is quit before and relaunched after from the bundle that was running (path
   recorded, launch verified); ASCII Sharks likewise only if it was running.
3. **The preview card** runs in the test identity with transient settings (nothing read or written).
4. **Calibration by eye** runs in the test identity on the built-in display alone: a launch option that keeps the
   test app to the main display (or a runbook step to detach the ultrawide), so the laptop density is what the
   director sees; the chosen count is noted, not saved to the owner's settings.
5. **The runbook** in `reports/t8.md` rewritten for this: exact commands, what the director does, how to stop at any
   point (nothing to restore but relaunching their app), and the results table.
6. Build the test bundle. Still nothing live: dry runs only, on the test domain.
Add a "Rewrite" section to `reports/t8.md`.

## Rewrite 2 (2026-11-21, after the re-check)
Read the re-check (`git show origin/review-t8:reviews/t8.md`, "Re-review (after fixes)") and the board's routing.
Keep the test identity as built (the re-check found it sound). Change:
1. **The script never touches the owner's apps.** Remove every quit, signal, relaunch and recovery record for the
   real ASCII Animals and ASCII Sharks. Instead, before any live mode, refuse to start (with a plain message: "Quit
   ASCII Animals and ASCII Sharks from their menus first") while any process whose executable path belongs to a
   real ASCII Animals or ASCII Sharks bundle is running. The runbook tells the director to quit their apps by hand
   first and reopen them after.
2. **Lock:** at a fixed path under the checkout's `build/` (not TMPDIR), atomic, never skipped by inherited state.
3. **Test-process identity:** by the executable's real path inside `build/ASCII Animals Test.app` and its bundle ID,
   rechecked right before every signal; a test copy already running from anywhere is refused before a baseline.
4. **Sampling:** reject malformed, duplicate or truncated rows and short series; report fps per display with the
   sampled screen count checked against the mode; record the power state throughout the run, and reject runs on
   battery or in Low Power Mode.
5. **Calibration and preview:** succeed only after the director types the count (calibration) or "seen"
   (preview); a built-in display must have rendered; print the numeric count used.
6. **Artefacts:** all test files (lock, scratch, logs) in one fixed folder under `build/`; the test copy's
   `--snapshot-*` outputs confined to it.
7. **Flags:** every test flag set explicitly (1 or 0) on each launch; the screen count verified.
8. **Runbook:** promises only what holds; the director's manual quit and reopen steps; a fallback when `recover`
   fails.
Nothing live. Add a "Rewrite 2" section to `reports/t8.md`.
