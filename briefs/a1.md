# Brief a1: root causes across the app (an audit, read-only)

Size: Review (one auditor; no code changes)
Board commit: the commit that adds this brief (main)
Code: `meadow-t11` @ 5e3dea9 (the whole 3.1 stack: Ocean, Web, Meadow, the app shell). Write `reviews/a1.md` on a new
branch `review-a1` made from main; commit only.

## Why
The director: "fix root cause and not symtoms, check if other root issues are lurking in the app as a whole and in
its details". Today's live session and the director's friends found several problems that were each first explained
as one-off symptoms. Find the **causes underneath**, and any other cause of the same kind that hasn't shown itself
yet, across the whole app.

## Facts reported (from real Macs; do not take any explanation here as given, find your own)
1. On a friend's laptop, while a macOS popup was on screen, the wallpaper stopped reacting to the pointer (no
   stirring, no clicks) until the popup was dismissed; **the animals kept moving** the whole time. Which app owned the
   popup is not known; the app itself can show alerts (updates, the Sharks hand-over, errors, the uninstaller) and
   asks for notification permission.
2. On another friend's laptop with a full menu bar, the fish icon was behind the notch and the welcome's arrow
   pointed at nothing. (Routed: t11 fix round 1.)
3. The test copy's energy reading stopped for 14 s while one of its menus was open. (Routed: t11, fixed.)
4. The what's-new card closed on any click anywhere, so people could miss a once-only card. (Routed: t11 fix round 1.)
5. The card was placed on the screen the system reports for the icon, or `NSScreen.screens.first`, not the screen the
   user is working on. (Routed: t11 fix round 1.)

## Do
Read the app (`Sources/ASCIIAnimals`, and `Sources/OceanKit` where the app's behaviour depends on it). For each root
cause you find: the class of mistake (e.g. a behaviour that depends on which app is active, on the run loop's mode,
on a window's visibility versus being seen, on "the first screen", on wall-clock versus awake time, on the main
thread being free, on a permission or a system setting, on a single display, on the default locale, on sleep and wake
ordering), every place in the code it occurs (file:line), what a user would see and when, how sure you are and why
(evidence from the code and Apple's documented behaviour; say when something needs a live check), and the fix at the
cause (one principle that removes the whole class, not a patch per symptom), with the check that would prove it.
Explain fact 1 from the code: the precise cause, and whether it is specific to the app's own popups.

Rank by what users would hit. Include the small details (things that misbehave only at a corner, only on some Macs,
only after sleep, only with several displays or Spaces or full-screen apps, only in light mode or Calm or Low Power).
Do not report style, naming or the Meadow's look. Do not repeat what facts 2 to 5 already route, unless the cause
reaches further than those fixes.

## Rules
Read-only: no edits outside `reviews/a1.md`, no builds that launch the app, no windows on the owner's display, never
the owner's ASCII Animals, ASCII Sharks, ~/Applications or their defaults. `swift build` and
`swift run -c release OceanChecks` are fine. No local folder paths in the review. End with a short list: the root
causes, in the order to fix them, each with its files, so the manager can brief builders without file overlap.
