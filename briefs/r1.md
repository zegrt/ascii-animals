# Brief r1: desktop pointer input, fixed at the cause (audit a1, finding 1)

Size: Content

## Objective
On a friend's Mac, while a popup was up, the wallpaper stopped reacting to the pointer and the animals kept moving.
The audit (`git show origin/review-a1:reviews/a1.md`, finding 1, and "Fix order" item 1) traces two causes: the only
pointer source is an AppKit global monitor, which never receives events dispatched to ASCII Animals itself (its
alerts, Settings, About, the welcome, the card); and the router rejects a pointer whenever any foreign window's
bounding rectangle contains it, with no ordering or shape. Give desktop input **one contract** that holds whichever app
is in front, and fix both causes, in Ocean, Web and the Meadow alike. The director: "fix root cause and not symtoms".

## Do
1. **Prove the causes first.** For each, a check that fails on 971a216 (pure routing and a delivery model you can
   drive: own-app dispatch, foreign dispatch, a nested tracking loop, a stale cursor position at callback time, a
   transparent or display-sized foreign window rect, an Animals window above the wallpaper). If a claim of the audit
   turns out wrong, say so with evidence and don't fix it.
2. **One input contract** (the audit's "Fix and proof" for finding 1): a pointer source that sees both foreign and own
   dispatch (global + passive local monitors, never consuming events), the event's own location at event time, the
   pointer re-sampled once per simulation step from a common-mode source so hover clears and re-routes when windows,
   Spaces or delivery change (no synthesized clicks), clicks judged fresh against current windows in z-order with the
   app's own UI windows blocking like any other, and the 50 ms window cache invalidated on start, stop and geometry
   change. No new permission (no Accessibility, Input Monitoring or Screen Recording). Measure the window-list cost
   per step and keep it bounded.
3. **The same feel.** Ocean, Web and Meadow react as before when the desktop is exposed (the existing digests and
   pointer checks pass unchanged); the Meadow's still-pointer landing and clicks follow the new contract.
4. **A live trace for the manager** (not run by you): a `--snapshot-*`-free diagnostic logging, per pointer event,
   its source (global/local/sample), point, run-loop mode, the blocking window's pid/layer/rect if any, and the route
   decision, on the energy-test copy only, so a supervised session can tell which cause hit. List the scenarios to try
   (an Animals alert, Settings in front, another app's small modal, a notification prompt).

## Addendum (audit a2, the director's call, 2026-11-21)
Read `git show origin/review-a2:reviews/a2.md`, "Hot-path audit across the app" (end of finding 9). Today a moving
mouse asks for a fresh `CGWindowListCopyWindowInfo` and bridges its dictionaries up to about 20 times a second, plus
on every click, and each motion fetches desktops and rects again. In the pointer contract you are building: keep one
snapshot of displays and occluding windows per input tick and refresh it on the events that change it, coalesce
motion to at most one pending sample per useful tick, and skip pointer work entirely when interaction is off or no
screen is eligible. Clicks stay immediate and exact; the dwell and breeze behaviour stays the same. Add a check that
counts window-list reads for a burst of moves, and report the before and after counts. Same files as above.
